# dialect-duckdb — DuckDB 方言插件

idb_engine 的 **DuckDB 方言实现** —— **本地嵌入式 OLAP 列式数据库**。v2.7 新增，第 4 个方言。

> **当前版本**：v2.9
>
> 架构与 SPI 接口定义见 [`api/README.md`](../api/README.md)。

---

## 元数据

| 属性 | 取值 |
|---|---|
| `driverName` | `"Duckdb"` |
| `displayName` | `"DuckDB (Embedded OLAP)"` |
| `jdbcDriverClassName` | `"org.duckdb.DuckDBDriver"` |
| `connectionType` | `EMBEDDED` |
| `requiresHost` / `requiresPort` | `false` |
| `supportsUser` / `supportsPassword` | `false` |
| `supportsSchema` | `true` |
| `supportsCrossDatabase` | `true`（`ATTACH` 多文件） |
| `jdbcUrlExample` | `jdbc:duckdb:/path/to/data.duckdb`（或 `:memory:` / `.csv` / `.parquet` / `.json` / `.xlsx`） |
| `capabilities` | `VIEWS, INDEXES, FOREIGN_KEYS, MULTI_SCHEMA, EXPORT, EMBEDDED_MODE` |

> **注意**：早期文档标注"无 `ROUTINES`"，但 v2.9 起 DuckDB 方言**声明** `ROUTINES` capability —— DuckDB 通过 `MACRO` / 标量 `FUNCTION` 实现 routine 概念；UI 据此决定显隐。

**不支持的能力**：
- ❌ `USERS` / `PRIVILEGES`（嵌入式无用户权限）
- ❌ `TRIGGERS`（SPI 默认 UOE）
- ❌ `DDL_TRANSACTION`（DuckDB 不支持 DDL 回滚）

## 连接约定

`buildJdbcUrl(host, port, database)` 返回 `jdbc:duckdb:<database>` —— host/port 完全忽略，**`database` 字段承载 URL 主体**。

| database 取值 | 实际 DuckDB URL | 用途 |
|---|---|---|
| `""` 或 `":memory:"` | `jdbc:duckdb:` | 嵌入式内存模式（每连接私有） |
| `"/path/data.duckdb"` | `jdbc:duckdb:/path/data.duckdb` | 本地 DuckDB 文件（多连接共享，文件锁） |
| `"/path/data.csv"` | `jdbc:duckdb:/path/data.csv` | 直查 CSV 文件 |
| `"/path/data.parquet"` | `jdbc:duckdb:/path/data.parquet` | 直查 Parquet 文件 |
| `"/path/data.json"` | `jdbc:duckdb:/path/data.json` | 直查 JSON 文件 |
| `"/path/data.xlsx"` | POI 预转换 → 临时 DuckDB | 透传 Excel（见下） |

**流式查询配置**：DuckDB 流式读取无需关闭 `autoCommit`（PG 才需要）。

## Excel 预转换机制（v2.7 关键设计）

DuckDB JDBC 不直接支持 `.xlsx`。`ExcelToDuckDbCache` 解决：

1. 检测到 `.xlsx` / `.xls` 文件 → 解析为 `List<Map<String, Any>>`
2. 用 Apache POI 5.5.1 `SXSSFWorkbook` 流式读取（百万行不 OOM）
3. 创建临时 DuckDB 文件，写入数据
4. **缓存 key = Excel 文件 path + size + lastModified** —— 重复访问同一 Excel 不重复转换
5. 业务层继续走 `jdbc:duckdb:<temp_file>` 标准路径

## 方言特性

| 特性 | 实现 |
|---|---|
| **Schema 导航** | 内置 `main` / `temp` schema；`ATTACH` 多个文件作为 alias；`listSchemas` 返回 `[main, temp, ...attached]` |
| **search_path** | `SET schema = "<name>"` |
| **自增主键** | `GENERATED BY DEFAULT AS IDENTITY`（DuckDB 1.5.5.1 不接受 IDENTITY + 表级 PK 组合；走 `SEQUENCE + DEFAULT nextval` 兜底） |
| **MODIFY COLUMN** | `ALTER TABLE ... RENAME COLUMN`（不支持类型 / nullable / default 改写） |
| **GET_DDL** | 原生 `SHOW CREATE TABLE name`（≥0.10）；失败时回退从 `information_schema` 重建 |
| **FK 管理** | **table-rebuild 路径**（DuckDB 不支持 `ALTER TABLE ADD/DROP CONSTRAINT` + 忽略 `CONSTRAINT fk_name` 子句名 → 自动生成 `<table>_<cols>_fkey`） |
| **FK ON DELETE/UPDATE** | 不支持 `CASCADE` / `SET NULL` / `SET DEFAULT` —— 全部改写为 `NO ACTION` |
| **Routine** | `duckdb_functions()` + `macro_definition` 列（不是 PG 的 `definition`/`description`） |
| **Routine 约束** | `duckdb_constraints()` 无 `column_name`，只有 `constraint_column_names (LIST)` |

### SQL 危险关键词（方言层 `validateSqlFragment`）

通用集合 + DuckDB 禁用：`INSTALL` / `LOAD` / `EXPORT` / `COPY` / `SET` / `RESET` / `CALL` 等 DuckDB 管理语句。

---

## 已知约束

- **不支持 DDL 事务**：CREATE / ALTER / DROP 一旦提交不可回滚
- **FK 子句名被忽略**：用户传 `fk_name="my_fk"` 实际写入 DuckDB 时被改写为 `<table>_<cols>_fkey`
- **内存模式不共享**：每个 `:memory:` 连接都是独立数据库实例（PoolManager 不会跨连接复用）
- **同文件多连接冲突**：测试 fixture 强制走 `PoolManager` 而非 DriverManager，避免连接配置冲突
